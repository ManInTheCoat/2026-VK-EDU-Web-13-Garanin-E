# Проект Nice Answer

## Как запустить проект через Docker Compose (Настоятельно рекомендуется!)
Поскольку проект использует микросервисную архитектуру (PostgreSQL, Redis, Celery, Centrifugo, Maildev), самый быстрый и надежный способ запуска — через Docker.

1. Убедитесь, что у вас установлен Docker и Docker Desktop запущен.
2. Скопируйте файл `.env.example` и переименуйте его в `.env.docker`.
3. Скопируйте файл `centrifugo.example.json` и переименуйте его в `centrifugo.json`.
4. В терминале в корне проекта выполните команду для сборки и запуска контейнеров в фоновом режиме:
   `docker compose up --build -d`
5. Примените миграции внутри контейнера веб-сервера для создания структуры БД:
   `docker compose exec web python manage.py migrate`
6. **Соберите статические файлы** для их быстрой отдачи через Nginx:
   `docker compose exec web python manage.py collectstatic --no-input`
7. Сгенерируйте тестовые данные (пользователей, теги, вопросы, ответы):
   `docker compose exec web python manage.py fill_db --ratio 10`
8. Создайте суперпользователя для доступа в панель управления:
   `docker compose exec web python manage.py createsuperuser`
9. Проект будет доступен по стандартному адресу (через Nginx): http://127.0.0.1/
10. **Для просмотра тестовых email-уведомлений откройте интерфейс Maildev:** http://127.0.0.1:1080/

## Как запустить проект локально (Без Docker)
> Для полноценной работы всех функций (веб-сокеты, кэш, фоновые задачи, email) вам потребуется вручную установить и запустить PostgreSQL, Redis, Centrifugo и Maildev, а также открыть отдельные терминалы для запуска `celery worker` и `celery beat`. Обратите внимание: локальный запуск использует встроенный сервер разработки Django и идет в обход Nginx.

1. Убедитесь, что у вас установлен Python версии 3.12 или выше.
2. Создайте виртуальное окружение:
   `python -m venv venv`
3. Активируйте виртуальное окружение:
   * Windows: `venv\Scripts\activate`
   * Mac/Linux: `source venv/bin/activate`
4. Установите зависимости:
   `pip install -r requirements.txt`
5. Настройте и запустите необходимые базы данных и сервисы (включая создание файла `centrifugo.json` из шаблона).
6. Скопируйте файл `.env.example` в `.env.local` и заполните его своими данными для локального подключения.
7. Примените миграции для создания таблиц в базе данных:
   `python manage.py migrate`
8. Заполните базу тестовыми данными:
   `python manage.py fill_db --ratio 10`
9. Запустите локальный сервер Django:
   `python manage.py runserver`

## Отчет о производительности серверов (Nginx + Gunicorn)

В рамках настройки production-архитектуры было проведено тестирование производительности.

**Инструмент и условия тестирования:**
Тестирование проводилось с помощью утилиты `ab` (Apache Benchmark) изнутри контейнера Nginx (чтобы исключить сетевые задержки хост-машины). Для статики и кэша отправлялось по 5000 запросов, для WSGI (Gunicorn) — по 1000 запросов. Уровень параллелизма (concurrency) — 100 потоков.

**Полученные метрики (Requests per second):**
* Отдача статического документа напрямую через Nginx: **342.10 RPS**
* Отдача статического документа напрямую через Gunicorn: **38.58 RPS**
* Отдача динамического документа напрямую через Gunicorn: **12.42 RPS**
* Отдача динамического документа через проксирование Nginx (без кэша): **12.55 RPS**
* Отдача динамического документа через проксирование Nginx (с proxy_cache): **7331.06 RPS**

### Выводы
**1. Насколько быстрее отдается статика по сравнению с WSGI?**
Статика через Nginx отдается примерно в **27.5 раз быстрее** (342 RPS против 12 RPS), чем генерация динамики через Gunicorn. Nginx читает файлы с диска асинхронно, в то время как Python тратит время на тяжелую бизнес-логику и работу с базой данных. Даже если заставить Gunicorn отдавать статику (38 RPS), он делает это в 9 раз медленнее Nginx.

**2. Во сколько раз ускоряет работу proxy_cache?**
Кэширование ускорило отдачу динамических страниц примерно в **584 раза** (с 12.55 RPS до 7331.06 RPS). Использование `proxy_cache` позволяет Nginx брать готовую сгенерированную страницу из оперативной памяти и отдавать её клиентам, вообще не обращаясь к Python-серверу, что дает колоссальный прирост производительности.
